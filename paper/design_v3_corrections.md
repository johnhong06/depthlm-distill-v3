## C-1 (2026-09-30, 확정) 배분 축은 "이미지 수 vs 픽셀 수" — 장면 다양성을 주장하지 않는다

### 근거 1: DepthLM Finding 4 는 다양성 실험이 아니다 (원문 전문 재확인)

- Finding 4 의 근거는 **Fig. 4c 하나**이고, 캡션은 "Accuracy with different number of **training samples**" —
  샘플 수 스케일링 곡선이다. 본문: "Before the dashed line (16M images), the model only sees 1 labeled pixel
  per training image, which already achieves over 0.8 δ1" [arXiv:2509.25413 §3.3].
- 즉 "Image diversity is more important than label density" 는 **"1픽셀/이미지로도 충분했다"에서 나온 해석**이지,
  다양성을 조작하거나 측정한 대조 실험의 결과가 아니다. 고정 예산(N·k 고정)에서 이미지 수 vs 픽셀 수 비교는 원문에 없다
  (전문 grep 재확인, D-3·design_v2_raw §22 와 일치).
- 저자들 스스로 최종 모델은 **2–4 px/이미지**(16M 이미지 × 23M–60M 샘플)로 학습했다 [§4] — Finding 4 를 문자
  그대로 따르지 않았다.
- 원문의 "다양성" 단위는 끝까지 **이미지**다. 유사 프레임 처리는 부록의 정성적 언급("highly similar video frames …
  do not help", 선별 기준 비공개)이 전부이고, 장면 수를 세거나 다양성을 수치화한 곳은 없다.

### 근거 2: "장면 다양성"은 우리 조건에서 증명 불가능하다

- 우리 장면 라벨은 촬영 메타데이터다(`01_count_scenes.py` docstring): SUN RGB-D kinect2/realsense/b3do 는
  캡처 1장 = 1장면이라 **같은 방 재촬영을 구분하지 못하고**(기록된 한계), KITTI raw 의 30초 구간은 임의 분할이다.
- 격자가 실제로 조작하는 변수는 이미지 수 N 이고, 장면 수는 N 의 결과로 따라오는 관찰값이다
  (mixed v4: N400→400 / N1600→1297 / N6400→3697 장면, 비선형). N 과 장면 수는 혼입돼 있어
  장면 인과를 말하려면 N 고정·장면 수만 조작하는 별도 arm 이 필요한데, 이는 추가 라벨링 예산이 들고
  장면 정의 한계도 그대로 남는다.

### 결정 (사용자, 2026-09-30)

> 장면 수를 나누는 것은 사실상 불가능에 가깝고, 다른 장면을 사용했다는 것은 증명하기 어렵다.
> 따라서 **이미지 수 vs 픽셀 수**로 간다.

- 배분 축 = **서로 다른 이미지 수 N × 이미지당 픽셀 수 k** (고정 예산 N·k).
- "서로 다른 이미지"의 기준은 **v5 dedup 으로 수치 고정**: 앞 N 장 안에 dHash(9×8) 해밍 ≤ 10 이면서
  32×32 회색조 상관 > 0.9 인 쌍이 없다 (`depthlm-distill-h200/experiments/07_dedup_pool_order.py`).
  이 기준은 재현 가능하고 코드로 증명 가능하다.
- **장면 다양성은 주장하지 않는다.** 장면 수·도메인 비율은 셀별 기술 통계로만 보고한다
  (G0 집계, `dedup_report.md` 의 장면 라벨 수).
- 논문에서의 문장: "같은 질의 예산에서, 근접 중복이 없는 서로 다른 이미지에 넓게 펴는 배분 vs 이미지당
  픽셀을 모으는 배분" — DepthLM Finding 4 의 단위(이미지)와 일치하므로 "원문 주장을 원문에 없는
  고정 예산 조건에서 검정"이라는 위치 설정이 정확히 성립한다.

### 영향

- `depthlm-distill/CLAUDE.md` 절대 규칙 5 수정 필요: "배분 축은 장면 단위로 정의" →
  "배분 축은 서로 다른 이미지 수(v5 dedup 기준)로 정의하고, 장면 수는 arm 별 기술 통계로 보고한다.
  장면 다양성을 인과로 주장하지 않는다." (수정 시점은 사용자와 확인)
- 구현은 이미 이 축과 일치한다(`02_build_pool.py` 의 N 조작 + 장면 상한, v5 dedup). 코드 변경 없음.
- 장면 상한(`--cap`)은 유지한다 — 다양성 "주장"의 근거가 아니라, N 축이 같은 드라이브의 반복 프레임으로
  채워지는 것을 막는 구성 장치로 서술한다.

## C-2 (2026-09-30, 확정) 격자 재정의: (예산 B × 배분 k) 완전 격자 — 모든 예산에 비교 대상

### 근거: 기존 격자의 결함

- 기존 격자(N ∈ {400,1600,6400} × k ∈ {1,4,16}, N·k ≤ 25,600 의 8셀)는 예산 행이 비대칭이다:
  예산 400 은 **셀 1개(N400k1)뿐이라 등예산 배분 비교가 불가능**하고, 1,600 은 2개, 6,400 은 3개, 25,600 은 2개.
- 원인: N 과 k 를 각각 격자로 잡고 상한으로 잘랐기 때문. 예산이 1차 축이 아니었다.

### 결정 (사용자, 2026-09-30)

**예산 B 를 1차 축, 이미지당 픽셀 k 를 2차 축으로 잡고 N = B/k 로 유도한다.**

| B \ k | k=1 | k=4 | k=16 | 등예산 비교 |
|---:|---|---|---|---|
| 400 | N=400 | N=100 | N=25 | 3-way |
| 1,600 | N=1600 | N=400 | N=100 | 3-way |
| 6,400 | N=6400 | N=1600 | N=400 | 3-way |
| (확장 25,600) | — (풀 한계) | N=6400 | N=1600 | 2-way |

- **k 집합 {1, 4, 16} 을 모든 예산에서 동일하게 고정** → 배분 처치가 예산과 독립적으로 정의되고,
  "저예산의 배분 순위가 고예산에서 유지되는가"가 B×k 상호작용으로 그대로 검정된다.
  예산 간격은 ×4 등비 — 뒤에 25,600, 102,400 을 붙여도 같은 규칙.
- 세 읽기 보존: 같은 행 = 등예산 배분, 같은 열 = k 고정·이미지 증가(이미지 한계효용),
  대각선(N 동일) = 이미지 고정·픽셀 증가(밀도 한계효용).
- **비용**: 기존 8셀은 전부 이 표 안. 새 셀은 (100,4)·(25,16)·(100,16) 셋뿐이고 앞 1,600장 ×16px
  기존 라벨의 부분집합 → **교사 질의 0**, 추가 학습 4,800 스텝 ≈ 37분/시드(로컬 0.458 s/step).
  중첩 유지: N ∈ {25,100,400,1600,6400} 전부 같은 순서의 접두사, 픽셀 인덱스 0..k−1 공유.

### 잡음 바닥 (사전등록 — 저예산 셀의 판정 조건)

- N=25·100 셀은 부분집합 운·시드 잡음이 배분 효과를 덮을 수 있다(시드 잡음 미측정, D-27).
- **반복 셀**(기존 라벨 안, 잡음 추정 전용): (25,16) 은 이미지 블록 0–24/25–49/50–74/75–99,
  (400,1) 은 픽셀 인덱스 0/1/2/3. 셀당 800스텝 ≈ 6분. 결정적 인터리빙이라 연속 블록의 도메인 비율 유지.
- 본 셀은 접두사(중첩 유지). **같은 예산 내 배분 차이는 반복 산포(잡음 바닥)를 넘을 때만 주장한다.**

### 예산 확장 규칙 (미리 고정)

"예산 B 에서 k ∈ {1,4,16} 중 N = B/k ≤ 풀 크기(6,400)인 arm 을 전부 포함한다."
B=25,600 부터 k=1 arm 은 풀 한계로 결측 — 결측으로 보고하고, 필요해지면 풀 뒤에 이미지를 추가(append)해
중첩을 깨지 않고 채운다.

### 영향

- `02_build_pool.py` 의 셀 정의(`--max_budget`/계단형)와 `arms.json` 을 (B, k) 파라미터화로 갱신하고,
  새 셀 3개의 rows_*.parquet 생성 필요 (라벨은 기존 것 재사용).
- `31_grid.py`·`32_decide.py` 의 등예산 비교 목록을 행 단위(각 B 의 k arm 쌍)로 갱신.
- 반복 셀 학습·집계 스크립트 신설 필요 (본 격자와 분리, 잡음 바닥 보고 전용).

## C-3 (2026-09-30, 확정) 학습 신호: soft 의 층위·거리 척도, GT 합산 손실 arm, 라벨 자릿수

### C-3a. soft = 최종 출력(자릿수 분포) KL 유지 + W1 파일럿 1셀

- **"어느 layer 를 증류하나"의 답**: 우리 soft 는 마지막 레이어(lm_head)의 다음-토큰 분포를 답 위치마다
  {0–9, ".", EOS} 지지집합으로 잘라 KL 로 맞추는 **response KD** 다 (`20_train_student.py` soft 분기).
  확률분포가 나오는 곳이 최종 레이어이므로 "분포 증류"는 본래 이 층위다.
- **중간 레이어 feature 증류를 배제하는 근거**: (i) 교사 Pixtral-12B(hidden 5,120, 40층) ↔ 학생
  Qwen2.5-VL-3B(hidden 2,048, 36층) — 층 대응·사영이 전부 임의 선택, (ii) feature 는 parquet 사전계산이
  불가능해 학생 학습 중 12B 교사 forward 가 필요 → "질의 1회 = 라벨 1개" 예산 프레임과 H200 패키징 붕괴,
  (iii) DepthLM 원문 "cross-entropy loss on the text tokens … no regression or regularization loss is
  needed" — 중간 레이어 MSE 는 원문이 불필요하다고 명시한 종류의 손실. 최종 분포 유지가 곧 원문 정합.
- **거리 척도 변형 (사용자 결정: KL 유지 + W1 파일럿)**: KL 은 자릿수를 명목형으로 취급(3 을 2 로 틀리든
  9 로 틀리든 같은 벌점). 같은 최종 분포 위에서 척도만 1-D Wasserstein 으로 바꾼 변형을 **한 셀에서만**
  파일럿으로 돌려 KL 대비 차이를 본 뒤 승격 여부를 결정한다. W1 은 값 공간(log-depth) 정의를 원칙으로
  한다(design_v2_raw 리뷰 판정: 자릿수 위 W 는 "원리 있는 부품" 주장 불성립). 파일럿 셀·정확한 수식은
  구현 전에 확정.

### C-3b. Loss_gt + Loss_pseudo arm 추가 (사용자 결정) — 절대 규칙 1 의 범위 수정

- **사실 확인**: 고전 KD(Hinton 2015)의 표준형이 L = α·CE(GT) + (1−α)·KL(teacher) 인 것은 맞다 —
  단 GT 가 있는 분류 설정. 반대 관행도 있다: Depth Anything V2 는 학생을 순수 의사라벨로만 학습
  [arXiv:2406.09414].
- **결정**: 본 격자는 Loss_pseudo 만 유지하되, **Loss_gt + Loss_pseudo 합산 arm 을 별도 실험**으로 추가한다.
- **정당성 조건 (이 arm 이 지켜야 할 것)**:
  1. GT 픽셀은 교사 질의 예산 밖의 **추가 정보**임을 표에 명시하고, 본 격자 셀들과 같은 행에서 순위 비교하지
     않는다(참조·상한선 성격). 기존 `--cond gt`(GT 단독 CE) 참조 arm 과 같은 지위.
  2. 절대 규칙 1("GT 는 학습에 쓰지 않는다")은 "**본 격자 학습에 쓰지 않는다. GT 합산은 명시된 별도 arm 에서만**"
     으로 범위를 수정한다 (CLAUDE.md 갱신 시 반영).
  3. 헤드라인("GT 0장 증류")은 본 격자 결과로만 주장하고, 합산 arm 은 "GT 를 추가하면 얼마나 더 오르는가"라는
     별도 질문의 답으로 보고한다.
- **구현 전 확정 필요**: GT 픽셀 출처·수(풀 소스 중 GT 보유: NYUv2·SUN RGB-D·KITTI dsel; 현재 라벨 parquet 의
  gt 열은 NYUv2 만), 합산 비율 λ(Hinton 형 α 또는 1:1), 어느 셀에 붙일지(권장: 본 격자의 최적 셀 하나).

### C-3c. 라벨 자릿수: 소수 첫째 자리 + 중간값 복호 유지, hard 1 vs 2자리 검증 ablation 실행 (사용자 결정)

- **원문 대조**: DepthLM 라벨은 "rounded to **two** decimal places … sufficient" [§3.2] — 원문은 2자리.
  우리는 1자리 절사 + 중간값(+0.05) 복호로 원문과 다르다.
- **1자리 유지의 실측 근거 (D-75, 옛 프로젝트)**:
  (a) 교사 값 해상도별 δ1: 2자리 원본 → 1자리+중간값 손실 ≤0.006 (0.8127/0.8865/0.6467 → 0.8087/0.8810/0.6436);
  (b) 교사 소수 둘째 자릿수 분포 엔트로피 2.285–2.298 nat (균등 = 2.303) = **사실상 균등** — 교사가 둘째 자리를
  모르므로 soft 로 둘째 자리를 증류하면 잡음을 가르치는 것;
  (c) 둘째 자리 분포 트리는 라벨링 forward 3–4배.
- **공정성 판단**: 격자 내부는 전 셀·전 손실이 같은 형식(고정값)이라 공정, 교사 대비도 같은 중간값 복호로
  채점하므로 공정. 기대 이득 상한 ~0.006 은 현 학생의 답 쏠림(D-27: "2.3" 최대 34 %)보다 한 차원 작다.
- **남은 공백과 처리**: hard 라벨 2자리가 학생 답 공간을 세분화해 쏠림을 완화할 가능성은 D-75 에서 ablation 으로
  예약됐으나 프로젝트 재시작으로 **미실행**(`resolution_runner.log` 빈 파일). 코드는 이미 지원
  (`20_train_student.py --decimals 2` + `teacher_full`). → **고정 부분집합에서 hard 1자리 vs 2자리 소형
  ablation 을 실행**해 실측으로 닫는다. 부분집합의 2자리 재라벨(teacher_full) 필요 — 같은 픽셀 재질의라
  예산 프레임과 무관한 검증 비용(옛 견적 10k px ≈ 1.8 h + 학습 2 × ~1.4 h).

## C-4 (2026-09-30, 확정) 학습·평가 데이터 정당성 재확인 + 레시피-혼합 비교 실험

### C-4a. 평가 지표 — 원문과 코드 레벨 동일 (닫힌 문제)

- 공식 `third_party/DepthLM_Official/utils/metrics.py:22` = `max(pred/gt, gt/pred) < 1.25`,
  우리 `depthlm_uncertainty/metrics.py:174` = 동일 정의(docstring 에 "공식 구현과 동일" 명시). AbsRel 은 표준 보조 지표.
- 실증: 교사를 우리 파이프라인으로 평가해 원문 재현 (D-26: nuScenes δ1 0.803 vs 논문 0.819 CI 안, DDAD 재현).

### C-4b. 평가 데이터셋 — 원문 8개의 진부분집합 4+1, 사유 기록 (사용자 결정: 유지)

- 원문 평가 8개: 실외 Argoverse2·DDAD·nuScenes / 실내 ScanNet++·SUN RGB-D·iBims-1·NYUv2 / 혼합 ETH3D [§3.1].
  우리는 iBims-1·NYUv2·DDAD·nuScenes + ETH3D(완전 held-out). nuScenes·DDAD 는 공식 curate 절차로 구축
  (`43_build_nuscenes.py` docstring).
- 제외 사유: **SUN RGB-D 는 우리 학습 풀이므로 평가 제외가 필수**(누수 방지 — 역할이 원문과 다름),
  ScanNet++·Argoverse2 는 용량·접근 제약. 도메인 균형(실내 2 + 주행 2)은 유지.
- 결정: 4+1 로 진행, 추후 필요 시 해당 데이터만 추가.
- 부기: 학습 풀 소스(SUN RGB-D·NYUv2·KITTI)는 교사 학습 소스와 무교집합 → "교사가 본 적 없는 이미지에서
  질의만으로 증류"가 성립. 풀-평가 누수 검사는 기존 기록(NYUv2 v4 장면 제외 등) 유효.

### C-4c. 도메인 분리의 정당성 — mixed = 원문 정합 조건, 분리 풀 = 진단 조건

- DepthLM 은 실내+주행 혼합(데이터셋 균등 샘플링, 주행 ≈49 %)으로 학습 [Appendix B Table 4]. 우리 mixed 50/50 이
  이를 증류로 옮긴 원문 정합 조건이고, indoor/driving 분리 풀은 도메인별 최적 레시피(배분×손실)를 식별하는
  진단 조건이다. 원문이 보지 않은 세부 질문이므로 이탈이 아니다. 평가는 자기 도메인 한정(기존 근거:
  교차 도메인 점수는 도메인 갭을 측정).

### C-4d. 레시피-혼합 비교 실험 (사용자 결정: 채택 + 게이트)

- **질문**: 균일 mixed 학습 vs "도메인별 최적 증류 레시피로 혼합 학습"(실내 부분은 실내 최적 (N,k,손실),
  주행 부분은 주행 최적) — 어느 쪽이 같은 예산에서 나은가.
- **위치**: 어느 쪽이 이겨도 원문과 충돌 없음. 균일 승 = 원문의 혼합 학습이 증류에서도 최선이라는 지지,
  레시피 승 = 증류에서는 도메인별 조정이 낫다는 정제.
- **사전등록 조건**:
  1. **실행 게이트**: indoor·driving 격자에서 32_decide 기준 '주장'(배분 또는 손실)이 최소 1건 나올 때만 실행.
     주장이 없으면 레시피-혼합은 잡음 비교이므로 하지 않고 그 사실을 보고.
  2. **예산 동일**: 총 질의 예산 = 균일 mixed 와 동일 (N_in·k_in + N_dr·k_dr = B).
  3. **선택 편향 통제**: 레시피는 도메인 풀 결과로 선정, 최종 비교 판정 규칙은 결과 확인 전에 사전등록.
  4. **구현**: 행 단위 손실·k 혼합 학습 필요 — `20_train_student.py` 의 `--cond` 가 런 전역이므로
     per-row 조건 지원 수정 필요 (중간 규모).
